# راه‌اندازی انتشار و آپدیت JETPiNG

این پروژه از GitHub Releases برای انتشار نسخه پایدار استفاده می‌کند. اپ نسخه جدید را از مخزن `ezzdigi/JETPiNG` بررسی می‌کند و فقط APK هم‌معماری با گوشی را می‌پذیرد.

## ۱) کلید امضای دائمی را فقط یک‌بار بساز

برای اینکه اندروید اجازه نصب آپدیت روی نسخه قبلی را بدهد، **تمام نسخه‌های آینده باید با همان کلید امضا شوند**. کلید را گم نکن و فایل آن را در مخزن GitHub قرار نده.

با JDK نصب‌شده، یک‌بار اجرا کن:

```bash
keytool -genkeypair -v -keystore jetping-release.jks -keyalg RSA -keysize 4096 -validity 10000 -alias jetping
```

یک رمز قوی انتخاب کن و فایل `jetping-release.jks` و رمزها را در محل امن و آفلاین نگه دار. اگر کلید گم شود، نسخه‌های بعدی نمی‌توانند روی نسخه نصب‌شده آپدیت شوند.

## ۲) چهار GitHub Actions Secret را ثبت کن

در GitHub به مسیر زیر برو:

`JETPiNG → Settings → Secrets and variables → Actions → New repository secret`

این چهار Secret را بساز:

| نام Secret | مقدار |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | محتوای Base64 فایل `jetping-release.jks` |
| `ANDROID_KEYSTORE_PASSWORD` | رمز keystore |
| `ANDROID_KEY_ALIAS` | مقدار alias؛ در دستور بالا `jetping` |
| `ANDROID_KEY_PASSWORD` | رمز کلید؛ اگر همان رمز keystore را انتخاب کردی، همان مقدار |

برای گرفتن Base64 در Linux یا Codespaces:

```bash
base64 -w 0 jetping-release.jks
```

خروجی را مستقیماً در Secret اول GitHub قرار بده. **فایل کلید یا رمزها را در کد، commit، Issue یا گفت‌وگو ارسال نکن.**

## ۳) انتشار نسخه جدید

هر نسخه باید شماره بالاتری داشته باشد؛ برای مثال بعد از `v1.0.0`، نسخه بعدی `v1.0.1` باشد.

در Codespaces یا ترمینال محلی:

```bash
git pull origin main
git tag v1.0.0
git push origin v1.0.0
```

به‌جای `v1.0.0` شماره نسخه واقعی را قرار بده. ارسال tag، Workflow انتشار را اجرا می‌کند. Workflow تست‌ها را اجرا می‌کند، APKهای امضاشده برای سه معماری و نسخه universal می‌سازد، checksum تولید می‌کند و در GitHub Releases منتشر می‌کند. اگر تست یا امضا شکست بخورد، انتشار کامل نمی‌شود.

## ۴) آپدیت داخل اپ چگونه کار می‌کند؟

- اپ نسخه پایدار جدید را از GitHub Releases بررسی می‌کند؛ نسخه‌های Preview به کاربران عادی پیشنهاد نمی‌شوند.
- بررسی فعلی پس از اتصال تونل انجام می‌شود تا درخواست بررسی آپدیت خارج از تونل ارسال نشود.
- وقتی نسخه جدید پیدا شود، کارت «نسخه جدید موجود است» در اپ نمایش داده می‌شود.
- دانلود و نصب مستقیم داخل اپ فقط وقتی فعال است که اتصال برقرار و پوشش تونل روی کل دستگاه باشد؛ در غیر این صورت دکمه صفحه Release را باز می‌کند.
- قبل از نصب، نسخه، نام بسته، معماری، امضای دیجیتال و SHA-256 فایل بررسی می‌شود.

## نکته مهم برای اولین نصب نسخه Release

اگر نسخه‌ای که اکنون روی گوشی نصب کرده‌ای با امضای Debug ساخته شده باشد، اندروید اجازه نمی‌دهد نسخه Release با کلید متفاوت روی آن نصب شود. برای اولین مهاجرت باید نسخه Debug را حذف و نسخه Release امضاشده را نصب کنی؛ حذف برنامه ممکن است داده‌های محلی آن را پاک کند. بعد از نصب اولین نسخه Release، نسخه‌های بعدی با همان کلید روی آن آپدیت می‌شوند.
